# Endpoint Testing and Validation

**Status:** Evidence recorded August 30, 2026

**Packages:** `smithy-php`, `aws-sdk-php`

## Scope

Validation covers the bytecode compiler, evaluator, source generator, cache
keys, resolver integration, AWS functions, and generated endpoint artifacts.

The evidence has three layers:

1. Focused Smithy runtime tests for compiler and evaluator behavior.
2. AWS tests for provider functions, opcode handling, and client integration.
3. Official service endpoint vectors evaluated through runtime-compiled and
   generated bytecode.

## Smithy Runtime Coverage

The Smithy endpoint tests cover:

- BDD node decoding and branch selection
- constants, registers, assignments, property access, and templates
- standard rules functions and invalid argument behavior
- endpoint, error, and value returns
- fused opcodes and generic function dispatch
- bytecode source generation
- static endpoint resolution
- operation input, context, and static parameter precedence
- L1 and L2 result caching
- cache namespace isolation
- generic and generated cache-key equivalence
- dynamic-client endpoint selection

The complete Smithy suite completed 1,784 tests with 5,033 assertions on PHP
8.2.33. It reported six PHPUnit deprecations.

## AWS Coverage

The AWS endpoint suite completed 94 tests with 186 assertions on PHP 8.2.33.
It covers:

- `aws.partition`
- `aws.parseArn`
- `aws.isVirtualHostableS3Bucket`
- `aws.stringEqualsIgnoreCase`
- AWS opcode handling
- endpoint authentication scheme aliases
- generated endpoint bytecode loading
- generated endpoint key builders
- client configuration integration

The suite is registered in `aws-sdk-php/phpunit.xml` and runs through the
`Endpoint Tests` PHPUnit suite.

## Lambda Conformance

The Lambda model supplies 71 endpoint test vectors.

Each vector runs through:

1. `BddCompiler` using the current Lambda model.
2. `LambdaEndpointBytecode`, generated from the same model.

Both evaluators must return the expected URL or the expected rules evaluation
error. This checks compiler behavior and verifies that committed generated
bytecode matches the model.

## Performance

The x86_64 endpoint benchmark used PHP 8.5.6, OPcache, tracing JIT, 100 warmup
iterations, and 10,000 measured iterations.

| Service and case | Uncached p50 | Cached p50 |
|---|---:|---:|
| S3 virtual addressing | 5,409 ns | 391 ns |
| S3 path style | 5,505 ns | 404 ns |
| S3 Express short zone name | 5,347 ns | 408 ns |
| S3 access point ARN | 11,663 ns | 404 ns |
| S3 Outposts ARN | 12,318 ns | 391 ns |
| Lambda, standard region | 1,393 ns | 159 ns |
| Lambda, GovCloud with FIPS and dual stack | 2,056 ns | 170 ns |

The warm result includes resolver lookup and cache-key construction. Successful
endpoint results use the resolver L1 and process-wide L2 caches. Evaluation
errors are not cached.

These microbenchmarks isolate endpoint evaluation and cache behavior.
End-to-end client benchmarking belongs in SDK-level performance reports.

## Current Gaps

Lambda validates one generated AWS service. Broader preview validation still
needs:

- generated endpoint vectors for S3
- representative services with simple regional rulesets
- endpoint authentication overrides used by S3
- catalog generation checks that load every emitted endpoint bytecode class
